# EvoKBase 快速开始

本文件保留简短的全流程导览。详细施工以[从零搭建操作手册](从零搭建操作手册.md)为准，其中包含逐章提示词、产物、失败恢复与验收；本页小节编号不作为详细手册的施工章节编号。

EvoKBase 是交给 AI 执行的操作手册。软件由执行 AI 使用官方安装方式直接安装；本仓库提供步骤、提示词、知识模板和日常 Hook 材料。只从新知识库开始，不导入或接管已有知识库。

团队使用时，先约定知识维护者、参与成员、共享资料范围及审核方式。下文“用户确认”指有权审核对应团队知识的人确认；普通成员可以提交候选，不能代替维护者批准。个人使用时由本人承担这些职责。

## 1. 交给 AI 的总任务

```text
请以 docs/从零搭建操作手册.md 为主教程，帮我们从零搭建团队知识库；本快速开始只用于了解整体流程。

先检查环境，确认团队知识维护者、共享范围、知识库目录、软件运行目录，以及是否启用 Horizon。
缺失信息只在会影响实施时询问；已经授权的步骤直接继续，不重复确认。
按照各软件当前官方说明直接安装和配置，不开发安装器或通用适配框架。
手册不指定版本；按官方要求选择兼容版本，记录实际版本与来源。
保留已有的无关配置，不覆盖同名角色，不在非空目录初始化知识库。
不使用 AGENTS.md 承载知识查询和评审调度，不恢复已停用的 EnsoAI Hook。
每个阶段完成后核对真实结果，失败时保留证据和恢复位置，修复后继续。
用户知识、凭据和实例配置保存在用户目录，不回填到 EvoKBase 仓库。
```

桌面环境使用 Obsidian 查看和编辑本地 Markdown，Codex 执行任务，GBrain 提供检索，Horizon 按需发现外部资料。Obsidian 的安装与打开 Vault 见详细主手册第 01 章，日常使用见第 02 章；服务器没有图形界面时在成员桌面验收。软件、镜像和模型不固定版本，安装时核对官方依赖要求。

执行 AI 先说明计划改动和位置。在既有授权内完成安装及配置；登录、原生信任等必须由用户完成的动作给出明确步骤。正式知识写入仍需用户确认具体正文或差异；公开发布、消息发送、删除数据和扩大外部数据使用范围遵守各自授权。

## 2. 环境和新目录

```text
检查操作系统、Git、Obsidian、Codex、Node.js 和可用的容器运行环境。
Node.js 用于配套 Hook；GBrain 的运行依赖以官方要求为准。
如启用 Horizon，再检查它需要的 Python、uv 等依赖。
已安装且兼容的组件直接复用，只安装当前步骤缺少的组件。

确定三个相互独立的位置：EvoKBase 手册、新知识库、软件及运行数据。
知识库目标非空就停止初始化，请用户提供一个新的目录。
检查 Codex 配置位置及同名角色、MCP 和 Hook，保留其他配置。
创建新知识库，在 04_系统维护/实例记录 中记录环境、路径和安装来源。
按Obsidian官方方式安装，用“Open folder as vault”打开这个新目录。
不要另建知识副本；编辑器与Agent读取同一条随机验收句，重启后再次核对。
```

实例记录包含实际软件版本、知识源标识、MCP 地址、数据位置、刷新命令和停止/恢复方法。认证信息使用软件支持的安全存储或私有配置，实例 Markdown 只记录位置或引用，不记录秘密值。

从零步骤先由维护者创建团队知识库。团队授权共享后，可使用独立的私有 Git 仓库维护正式 Markdown；成员同步获准版本，在各自机器配置角色、Hook 和本地检索实例。成员的绝对路径、账号和私有运行记录留在各自本机，共享文档只保存通用说明。团队知识仓库与 EvoKBase 公开手册仓库分开。

成员提出变更，由指定维护者审核并合并；刷新以已审核版本为准，合并前重新核对并发修改。共享文件可见性由实际仓库权限决定，提示词不能隔离已下发到本机的文件。此流程不包含中央检索服务或按成员过滤知识的权限平台；需要该部署方式时另行核对服务端权限和成员访问，再验证。

## 3. 知识结构与模板

```text
在新知识库中创建首页、收件箱和五层目录，复用 templates/knowledge-base。
不复制 EvoKBase 的 Git、测试、运行目录或本机资料。
阅读并采用知识录入说明；模板中 approved 只是示例，用户确认采用后才生效。
使用用户的 Git 身份建立本地版本记录，精确提交本次已确认文件，提交信息用中文。
不自动建立远程仓库或云同步。
```

| 目录 | 职责 |
|---|---|
| `00_资源库` | 原始资料和来源卡，保留原件 |
| `01_主题Wiki` | 可复用方法、问题案例、解决方案、踩坑经验 |
| `02_项目库` | 项目背景、约束、决策及原因 |
| `03_输出库` | 方案、复盘、评测等正式成果 |
| `04_系统维护` | 实例记录、八类模板、反馈、进化提案、恢复说明 |

验收：首页能导航到收件箱和模板；Markdown 按 UTF-8 独立可读；Git 中只有本次文件；未覆盖原始资料。暂时不需要的二级目录不提前创建。

## 4. 安装 GBrain 并验证 MCP

GBrain 提供检索服务，Markdown 保持为事实源。安装和依赖以 [GBrain 官方仓库](https://github.com/garrytan/gbrain) 为准，不分发作者的数据库、私人镜像或安装配置。

与 Horizon 一样，本章只提供操作说明和执行提示词，由 AI 完成安装、配置及验证。EvoKBase 不提供 GBrain 专用安装、部署、升级或刷新脚本；也不预设软件版本、镜像标签或固定部署组合。

```text
按 GBrain 当前官方安装说明，为新知识库部署独立的检索实例。
优先采用官方支持、适合当前本机环境的部署方式，直接执行原生命令。
不指定版本；安装时按官方要求选择兼容依赖，实际版本与安装命令记入我的实例记录。
先说明依赖、监听地址、数据库位置和停止方法，不编写 EvoKBase 安装器。

先实现关键词检索，不默认启用外部嵌入、查询扩展、重排、自动写回或生成型 Dream。
需要数据库或容器时使用新实例与独立数据目录；服务入口只绑定本机。
创建只读检索身份，检查实际 MCP 工具与参数，确保既能搜索也能读取完整原文。
角色侧工具限制与服务端只读权限都要验证，不能仅靠提示词保证只读。
把知识源、实际连接方式、认证引用、导入命令和刷新步骤写入实例记录。
```

导入前明确已获准的文件清单：默认正式范围为首页、主题 Wiki、项目库、输出库和知识录入说明中的已批准 Markdown。排除收件箱、草稿、模板、原始资料、隐藏目录、凭据和运行记录。Git 已提交并不代表内容已批准。

若所装 GBrain 无法直接按范围排除，执行 AI 可用标准文件/Git 命令，在知识库外创建仅含本次批准文件的派生目录，再注册为源；在实例记录写清如何同步新增、修改和撤回。不得把整个知识库导入后声称草稿已隔离，也不因此开发通用快照管理器。

验收：创建明确标记的合成测试页，通过 MCP 搜索并读取完整正文，核对来源；验证未授权草稿查不到、写操作被拒绝；更新和撤回测试页后刷新，再次核对结果。测试页不冒充真实知识。不启用语义向量时不要求同义召回，也不宣称已具备语义检索。

## 5. 配置查询与评审两个子 Agent

使用配套[查询提示词](../templates/codex/knowledge_retriever.md)和[评审提示词](../templates/codex/knowledge_reviewer.md)。配置格式由执行 AI 核对当前 [Codex 子 Agent 官方文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)后填写；手册不绑定特定 CLI 版本。

```text
将两个提示词模板中的 {{KNOWLEDGE_ROOT}} 和 {{SOURCE_ID}} 替换为实例实际值。
创建 knowledge_retriever 和 knowledge_reviewer 两个 Codex 原生角色。
按当前官方格式把提示词放入角色配置，使用只读权限，默认继承会话模型。
为需要的角色配置 knowledge_flow_gbrain MCP，核实实际工具合同与模板一致。
不把模板文件路径当成 developer_instructions 正文，不保留未替换占位符。
如名称冲突，先展示冲突，不覆盖；实际工具或格式不兼容时明确说明并调整材料。
配置已有内容只做必要的局部合并，备份本次修改，记录修改文件与恢复方法。
```

查询角色只返回原文证据，不承担主任务或推荐入库。评审角色独立核对任务证据与旧知识，最多推荐两条，给出 `skip / update / new / correction / observe` 中的实际结论。两者都不能自己批准、保存知识或递归委派。

问题、决策、方案、踩坑和完整案例都可以推荐；复用范围可以只在当前项目内。需要说明真实增量、复用场景、来源和适用边界。失败次数、总结篇幅或模型自评分不决定价值。

## 6. 配置原生 Hook 调度

Hook 是宿主在特定事件发生时执行的处理器。此处保留的 [knowledge-flow.mjs](../templates/codex/knowledge-flow.mjs) 只注入日常调度提示和记录少量事件元数据，由主 Agent 调用角色；它不安装软件，也不直接调用模型。事件配置和信任流程参见 [Codex Hooks 官方文档](https://learn.chatgpt.com/docs/hooks)。

```text
阅读配套 knowledge-flow.mjs，将它放在知识库外的独立运行目录。
建议采用 <Codex配置目录>/knowledge-flow/runtime/knowledge-flow.mjs。
按当前 Codex 官方文档在 hooks.json 添加以下事件处理器：
- UserPromptSubmit：普通消息注入查询与结案评审要求。
- SessionStart：仅匹配 compact，压缩恢复时核对已完成状态。
- SubagentStart / SubagentStop：仅匹配两个知识角色。

每个处理器调用实际 Node 可执行文件和脚本绝对路径；按系统正确引用含空格路径。
与已有 Hook 并存，不覆盖事件列表，不依赖处理器执行顺序。
不新增 Stop 强制续跑，不通过 AGENTS.md 调度。
按宿主提示让用户完成原生 Hook 信任审核，不改信任记录绕过审核。
```

处理器日志写在脚本目录的上一级 `events.jsonl`。使用建议目录时为 `<Codex配置目录>/knowledge-flow/events.jsonl`；不会保存问题和知识正文。运行文件与日志均不放入知识索引或开源仓库。

验收：新会话正常提问，确认查询角色真实启动并读取知识；形成任务结果后确认评审角色真实启动。问候可以由查询角色判断无需检索；取消或停止立即优先执行。角色不能递归派生；压缩恢复不能重复推荐。Hook 测试通过只证明处理器行为，不能替代宿主真实调用验证。

## 7. 首次入库与日常使用

```text
请用我授权的一份真实资料或已完成任务，验证知识处理闭环。
保留原件和来源，读取正文；查询旧知识并逐页读原文。
由评审角色判断新增、补充、纠偏、观察或跳过。
有候选时展示目标路径、来源、增量、适用边界及完整正文或精确差异。
等我确认具体内容后，重新核对证据与目标版本，再保存正式 Markdown。
使用 status: approved 标记获准正文，精确提交审核文件。
按实例记录的原生刷新步骤，仅同步批准范围，并检查失败与排除项。
在新会话通过 MCP 搜索并读取新正文，不能只检查命令退出码。
```

首次闭环之后正常提问即可，已信任的 Hook 提醒主 Agent 调用两个角色。任务没有潜在知识价值可跳过；证据缺失返回观察；不能把错误当未命中或假称旧知识不存在。正文保存但刷新失败时报告“已保存，索引待刷新”，修复后只补刷新。

完整规则见[知识录入说明](../templates/knowledge-base/04_系统维护/知识录入说明.md)。该步骤不使用已撤下的 EvoKBase CLI，实际刷新命令由安装时核对并记录。

## 8. 用真实反馈改进方法

```text
请从实际使用反馈中识别值得改进的知识方法。
先读当前方法和反馈证据，区分个别情况、事实纠偏和可复用规则。
使用反馈卡和进化提案模板，列出旧方法、建议变化、证据、范围和验证方式。
没有充分证据时保留观察，不因为出现多次就自动通过。
用户确认后更新正式方法、提交和刷新。
选一个同类任务，明确读取并采用新版本，记录实际结果与行为差异。
效果不成立时提出撤回或修订，确认后执行。
不自行修改两个 Agent 提示词、全局规则或用户偏好。
```

知识增加是积累；批准后的方法变化在后续任务中产生可验证改善，才是已验证的进化。没有长期使用证据时报告“闭环已搭建，效果待验证”。

## 9. Horizon 与日常维护

需要外部资料发现时，继续执行 [Horizon 外部知识模块](Horizon外部知识模块.md)。先手工完成一轮；定时运行、外发通知等按用户需求使用宿主或系统已有能力，不为手册额外开发平台。

软件维护直接遵循各组件官方说明。执行 AI 根据实例记录检查版本兼容、备份必要配置、升级并验证相关链路。停用时只移除本次知识角色和对应 Hook 项，保留其他配置及用户资料；数据删除和服务卸载另按用户授权执行。

恢复以 Markdown 和必要配置为主；先定位网络、权限、依赖、来源或刷新失败点，不清空数据库掩盖问题。具体命令、已完成阶段、待处理事项及恢复点留在用户实例记录，通用手册不回填私人信息。

## 10. 完成标准

知识库独立可读；新会话可搜索并读取正确原文；查询和评审角色有真实调用证据；至少一份真实资料完成确认入库；未批准文件不可检索；刷新失败如实呈现且能恢复；反馈提案与已验证改善分开记录。Horizon 或定时任务启用后，分别验证实际抓取、角色调用和调度结果。

报告已完成、失败和未验证项及其证据。完整检查见[验收说明](开发验收.md)，不以文件存在、软件启动或历史测试通过替代新用户环境验收。
