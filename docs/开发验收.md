## 新用户环境验收

| 环节 | 通过条件 |
|---|---|
| 环境与安装 | 仅按手册和官方来源完成；实际依赖、版本、目录与恢复方法有记录 |
| 从零边界 | 新目录初始化，不覆盖已有资料或无关宿主配置 |
| 模板 | 五层目录职责清楚，八类模板可用，示例未冒充用户经历 |
| 检索 | MCP 搜索后读取完整正文并核对来源；新会话也可复现 |
| 范围与权限 | 草稿、模板、原始资料等排除项不可检索；写工具被拒绝 |
| 真实调度 | 查询和评审两个原生角色有实际调用结果；无递归或重复推荐 |
| 知识质量 | 重复跳过，有增量才推荐；决策、方案、踩坑与完整案例保留证据 |
| 确认入库 | 展示全文或精确差异后由用户确认，保存前复查目标变化 |
| 刷新 | 只同步已批准范围；修改和撤回后检索结果一致，失败不假报成功 |
| 反馈进化 | 提案、批准、正式方法更新、后续使用效果可追溯 |
| Horizon（启用时） | 抓取成功/无新增/失败可区分，3+1 真实完成，原文复核，确认后可检索 |
| 定时运行（启用时） | 存在真实触发证据，能暂停和恢复，不自动扩大写入或发送范围 |
| 恢复 | 资料独立可读；必要配置与索引可恢复；其他用户配置保持完整 |

每项记录实际结果、证据路径、未验证内容和失败后的最小处理步骤。未启用的可选能力写“不适用”，未执行的写“未验证”，不能算通过。
