# 知识录入与受控进化

1. 保留原件和来源，标注真实阅读范围。
2. 查询已有知识并读取正文，判断补充旧文还是新建完整案例。
3. 记录问题、决策及原因、有效方案、失败边界和验证结果；项目内复用也有价值。
4. 展示拟写入全文或精确差异，用户确认后保存正式 Markdown，设置 `status: approved`。未确认内容使用 `draft`、`proposed` 等状态。
5. 使用用户自己的 Git 身份精确提交已审核文件。不要暂存无关资料。
6. 核对已批准的提交和实际索引文件清单，按实例记录中的 GBrain 原生步骤刷新。缺少记录时先查所装版本帮助并补齐，不猜命令。初始化模板是使用约定，不代表用户的业务经历。
7. 刷新完成后在新会话检索并读取新正文。失败则明确报告“正文已保存，索引待刷新”。

默认只允许首页、主题 Wiki、项目库、输出库和本说明中已批准的 Markdown。资源原件、模板、收件箱、隐藏目录和草稿不进入索引；不要通过复制位置绕过审批。`approved` 是可检查的状态标记，不是用户确认的替代品。

反馈记录保留用户原话。需要改进方法时，在进化提案中列出旧方法、新方法、证据、影响、验证和撤回方式；用户批准后更新正式方法并刷新。下一次验证任务明确引用该方法，由查询子 Agent 读取新版本，记录实际行为差异。没有验证差异不能称为进化成功。不自动修改 Agent 提示词或全局规则。

默认先配置关键词检索，不启用外部嵌入、查询扩展或重排；实际启用状态以实例记录为准。两个 Agent 默认继承 Codex 当前会话的模型；读取的知识可能进入该模型的上下文。Hook 只注入调度要求，真实执行仍需核对宿主调用记录。
