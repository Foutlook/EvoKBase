# 知识门户（P1—P4）

从同一份本地 Markdown 读取目录、正文、文件头和附件。本地浏览无需 GBrain、Obsidian 进程或模型连接；可选搜索复用现有 GBrain。网页可将 Markdown 保存到独立暂存区，不写正式知识库或执行 Git；审核后的发布由独立命令衔接既有通道。

## 启动

需要 Node.js 22 或更新版本。在本目录运行 `npm ci --ignore-scripts`。将下面的配置另存到**公开仓库与知识目录之外**，把 `root` 换成自己的知识库绝对路径：

```json
{
  "root": "/absolute/path/to/your/vault",
  "include": ["首页.md", "收件箱.md", "00_资源库", "01_主题Wiki", "02_项目库", "03_输出库", "04_系统维护"],
  "exclude": ["04_系统维护/自动运行", "04_系统维护/质量闸门"]
}
```

`include` 是必填的展示白名单，支持文件或目录；`exclude` 在其上进一步排除文件/目录，均使用 `/` 分隔的库内相对路径，不使用通配符。按自己的目录调整，尤其应排除含私有凭据或运行记录的文档。文件名和扩展名过滤不能判断任意 Markdown 正文是否含敏感信息。

```sh
node server.mjs --config /path/outside/repository/portal.local.json
```

打开 `http://127.0.0.1:4317`。端口占用时附加 `--port 4318`。只监听 IPv4 回环地址，使用上述地址而非 localhost。按 Ctrl+C 关闭；不安装系统服务，不写浏览缓存或查询日志。启用导入后会保存暂存原件、草稿和任务状态。不要通过反向代理或隧道开放给其他机器。

## 使用与边界

- 左侧目录支持按文件名/路径定位；它不是 GBrain 搜索。正文每次打开或点击刷新重新读取，可看到 Obsidian 保存后的修改。
- WikiLink 支持路径、别名、标题锚点；裸文件名只有唯一匹配时才导航，同名不猜测。Markdown 相对链接按当前文件目录解析。链接指向展示范围外时显示未解析。
- 标题锚点以可见标题生成，空白转 `-`，字母转小写；重复标题使用 `-1`、`-2`。块引用 `^id`、笔记嵌入、Obsidian 插件、Mermaid 和数学公式暂不渲染，笔记嵌入提供原文链接。
- Frontmatter 以原始文字展示，不执行 YAML 标签或模板。代码块内的 WikiLink 保持代码。
- 附件页提供打开及下载入口：PNG/JPEG/GIF/WebP 预览，PDF 交给浏览器，TXT 以文本打开，DOCX 下载。部分内嵌浏览器无 PDF 阅读器，可下载后用本机应用打开；SVG、HTML、脚本及其他格式不提供文件入口。文档上限 4 MiB、附件 64 MiB。
- 原始 HTML 转义，远程图片不自动加载；外部 HTTP(S)/邮件链接需点击打开，不携带来源页面地址。页面通过内容安全策略限制脚本和资源来源。
- 隐藏目录、临时目录、日志/备份/凭据目录及 AGENTS/计划记录默认隐藏。路径穿越、Windows 数据流、符号链接和目录联接受限；浏览入口只接受 GET/HEAD。专用导入暂存入口额外接受同源 POST，并检查 Origin、自定义请求头和 JSON 类型；所有入口检查 Host 和跨站请求。
- 本机无登录模式以操作系统账户为信任边界；它不是防御同账户恶意进程并发替换文件的沙箱。读取本地未发布正文不代表内容已审核或已进入索引。

## 关系图谱（P2）

界面从左到右分为三栏：功能图标栏（首页、关系图谱）、文件树、正文或图谱内容区。首页文件也保留在文件树内；展开画布仅收起文件树，功能栏仍可导航。图谱使用独立地址 `/?view=graph`，不依赖当前文档成功读取；从文档进入时保留该文档作为一跳视图的上下文。默认显示全部展示文档的力导向图：圆点代表文档，细线代表引用，关联越多的节点越大。拖动节点调整位置，拖动空白处平移，滚轮或加减键缩放，方向键平移；悬停或键盘聚焦节点突出关联，点击节点打开正文。拖拽超过点击阈值后松手不会打开文档；“适应画布”收拢全部节点，“展开画布”临时隐藏目录。初始比例优先保证可读性，远处孤立节点可通过平移或适应画布查看。

右上角齿轮内可切换当前文档的一跳关系，按文件名/路径包含文字筛选，隐藏孤立节点，按文字匹配设置颜色分组，调整节点/文字/连线及力学参数。默认不显示箭头；启用后箭头从引用方指向被引用方。设置仅保留在当前页面，不写知识库或 Obsidian 配置。筛选后只显示所选节点之间的关系，一跳视图始终保留当前文档。下方折叠的“引用明细与原文位置”保留反向引用与文字访问入口。

视觉和操作参考 [Obsidian Graph view](https://help.obsidian.md/plugins/graph)，没有复制其应用代码；[Obsidian 应用代码保留权利](https://obsidian.md/license)。布局、拖拽与缩放使用开源 [D3 7.9.0](https://github.com/d3/d3)（ISC），从本地依赖提供脚本与 `/vendor/d3.LICENSE`，不通过 CDN 加载。当前不是全部 Obsidian 功能的复刻：没有时间轴、标签/附件节点、完整搜索语法或多跳深度控制；沿用本应用已有的引用解析范围。

每组关系保留所有引用发生位置：正文使用所属段落或表格行的行号范围，文件头使用 YAML 字符串字段的范围。点击位置可回到来源正文或展开文件头；链接携带来源文件摘要，文件变化后明确提示旧位置可能失效。同一对文档的多次引用合并成一组，原始位置分别保留。

正文沿用 P1 的 Markdown/WikiLink 解析。文件头通过 [yaml 的文档节点接口](https://eemeli.org/yaml/#parsing-documents)读取字符串值，再复用同一链接解析器；只认字符串内明确写出的 WikiLink 或 Markdown 链接。普通主题、项目、标签名称、裸路径、注释和代码示例不推断为关系，不展开 YAML 别名或执行自定义标签。语法错误的文件头提示警告，正文继续可读。

图谱仅含展示范围内的 Markdown 文档。外部网址、附件不作为文档节点；同名、失效、不可读目标及不存在的标题锚点单列为未解析，块锚点暂不支持。不可读文件不会使其他文档的图谱失败。

每次请求从当前文件重建，页面内只保留本次结果，点击刷新重新读取；不创建持久图数据库或正文缓存。对大库还未做性能承诺，只有实测变慢时才增加按内容摘要失效的应用缓存。图谱是逐文件读取的快照，不是文件系统事务；可以通过刷新重建。停止或不打开图谱不影响正文、Obsidian、原检索与入库。

## 搜索知识（P3）

功能栏的放大镜打开 `/?view=search`，文件树保持在中栏。关键词或问题提交到服务端，调用现有 `recall({query, limit:10})`，保留结果片段和返回顺序；不显示 facts 分支，不做生成回答、重排、新索引或模型配置。搜索词保存在当前页面 URL 中，便于返回结果页；应用不记录查询日志。目录筛选仍只按文件名/路径过滤。

在仓库外的实例 JSON 中增加可选 `gbrain` 对象：`{"url":"https://your-internal-mcp.example/mcp","sourceId":"your-source"}`。该地址须是已有授权的**无状态 Streamable HTTP MCP** 接口，目前支持 JSON 和有限 SSE 响应，复用接口原有只读授权。未实现 OAuth、Bearer 配置或有状态会话；需要这些方式的部署须先补适配，不能关闭认证来迁就门户。地址只在服务端使用，不接受网页传入的上游地址、工具名或来源参数，不接受 URL 内账号密码、重定向和 `__all__`。未配置、网络失败或 12 秒请求超时，明确提示搜索不可用，本地浏览不受影响。

每条命中通过 `get_page({slug, source_id, include_content:true})` 核对所配来源。旧接口可能不返回命中的 source_id，此时还核对片段是否出现在所配来源的规范化原文中；分块合并的空白只在这一步统一。来源或片段核对失败保留结果但不生成本地链接。搜索范围继承 MCP 原有权限，可能大于网页文件白名单，因此片段仍可能来自展示范围外；门户不擅自修改搜索范围或静默删除结果。

本地链接仅从允许展示的 Markdown 清单产生，复用既有路径及符号链接检查。路径身份兼容所验 GBrain 0.47.7.0 的大小写、空格、Unicode、标点规范化及合法 frontmatter slug；同一身份对应多个文件时不猜测。范围外、移动/删除、无法映射的原文明确标识；完整索引原文也只对可唯一映射的展示文件提供。特殊前缀导入、别名身份和未来版本规则变化未承诺自动兼容，不以文件名模糊匹配兜底。规范化适配的 MIT 声明见 `THIRD-PARTY-NOTICES`。

标题打开**当前本地文件**；折叠区查看**索引中的规范化 Markdown 原文**及更新时间、索引摘要、本地文件摘要。正文比较只统一换行和首尾空白并去掉本地文件头，与 `compiled_truth` 比较；一致不代表文件头一致或发布完成，不同也可能来自索引转换。两种摘要口径不同，不能相互比较；页面更新时间不代替刷新回执的 Git 版本。实际发布状态仍按原有审核、提交、推送与刷新回执确认。未发布内容不会因打开门户而进入搜索。

## Markdown 导入（P4）

在实例配置中增加以下可选字段，绝对路径与远程地址均替换为自己的既有部署值：

```json
{
  "imports": {
    "directory": "/absolute/path/outside-vault-and-repository/imports",
    "resourceRoot": "00_资源库/外部资料",
    "publish": {
      "remote": "origin",
      "remoteUrl": "git@github.com:YOUR-ACCOUNT/YOUR-PRIVATE-VAULT.git",
      "repository": "YOUR-ACCOUNT/YOUR-PRIVATE-VAULT",
      "workflow": "refresh-knowledge.yml"
    }
  }
}
```

暂存目录不能在知识库或应用仓库内，也不能是知识库的祖先目录，不接受符号链接或目录联接。未配置 `imports` 时，浏览和搜索仍可用；仅暂存无需配置 `publish`。身份认证沿用本机 Git/gh，不在网页输入或保存凭据。

功能栏的“导入资料”打开 `/?view=imports`。Markdown 接受单个 UTF-8 文件，最多 4 MiB，原件字节保持不变；无效文件头或固定 `slug` 拒绝导入，避免搬移后与旧索引身份冲突。Markdown 附件、图片、外链不会抓取或解析，网页明确列出未读取范围。DOCX / PDF 的本地解析见下节；OCR、旧 DOC 和网址抓取仍后置。

页面预览正文、完整 Markdown、原始资料卡和全部拟新增文件，另可下载完整原件。资料卡复用仓库既有模板，初始保留 `unread`、低置信度和未读取范围；文件解析不代表已阅读或已批准知识结论。可修改资料卡与目标子目录；保存后全部产物摘要、精确路径及解析范围共同产生新的确认版本。未保存编辑时阻止应用内刷新、切换任务和上传覆盖，离开页面由浏览器提示。

导入时选择已有主题分类或输入新分类，层级使用 `/` 分隔。候选来自资源目录，资料包和图片目录不作为分类。分类与归档目录联动，保存时将分类各层写入资料卡 `topics`，移除原分类标签并保留其他主题。未分类草稿仍可暂存，但审核交接和首次发布会拒绝；修改分类必须重新确认版本。历史发布任务保留当时的清单，后续已批准的目录整理以知识目录及对应 Git 记录为准。

“导出审核交接任务”提供本机待审材料，交给已有 Codex 渠道读取核对来源、敏感性、重复、阅读范围及文件清单。必须获得用户对具体版本及私库发布范围的确认，才能由原渠道保存 `approved` 回执。交接里的 `pending` 示例不是审核证据；修改 `status` 不会自动批准。回执绑定任务、内容版本、审核人和可定位的审核/确认记录，它是本机工作流程交接，不提供独立身份认证。

在本目录通过独立命令发布：

```sh
node publish.mjs publish /outside/portal.local.json TASK-ID /outside/approved-receipt.json
node publish.mjs check /outside/portal.local.json TASK-ID
node publish.mjs retry /outside/portal.local.json TASK-ID
```

`publish` 仅允许正式库根目录的 `main`，核对远程读写地址、本地与远程版本及全部未提交/暂存内容。目标目录已存在或有其他待推送提交时停止，不覆盖文件，不整理无关修改。批准后只新增清单内文件：Markdown 为 `原文.md` 与 `原始资料卡.md`；DOCX / PDF 另有解析正文与图片。逐份核对暂存及提交字节；推送这个提交后由既有 P9 工作流刷新，不再调用旧刷新入口。停止使用门户不影响旧流程。

`check` 按该提交检查既定 GitHub 工作流、固定刷新回执、提交祖先关系、全部文件字节、清单内 Markdown 的索引正文与本地摘要，以及原件哈希能否召回资料卡。二进制原件和图片不冒充已索引正文。只有这些检查通过才记为完成；仅推送成功或工作流成功不够。需配置 P3 的 GBrain 接口并把导入目标包含在展示范围内。`retry` 只重跑同一已失败工作流，不生成新提交；成功或运行中的任务不重跑。

任务保存写入、提交、推送与刷新阶段，重试核对已有文件和提交，避免重复写入。后续编辑、远程变化、哈希不符或缺失证据会停止自动恢复；不会执行 reset、stash 或整库清理。每个个人实例使用一把导入锁，进程崩溃时保留锁。核对 `.import.lock` 后，仅当其进程已结束、SHA256 仍匹配时，可以运行 `node publish.mjs unlock /outside/portal.local.json LOCK-SHA256`。仍在运行或无法确认的进程不解锁。

已完成隔离验证、本机暂存 UI，以及一份用户确认的真实 Markdown 的私库发布、P9 刷新、新资料检索与网页打开验收。原库有无关修改时，本次使用独立干净副本发布，再将原库快进到精确提交，原有修改字节保持不变；CLI 不自动管理这些副本。Windows Git 检出可能自动转换换行，导致正文等价但原件摘要不同；从发布副本同步时应在命令级使用 `-c core.autocrlf=false`，并核对批准摘要，不降低原件字节检查标准。个人实例证据留在仓库外。

单次实例成功不代替其他部署验收或人工 IDE 端到端审阅。没有网页自批入口、自动知识提炼、多用户权限或后台发布队列。

Markdown 渲染采用 [markdown-it](https://github.com/markdown-it/markdown-it)，按其[渲染规则](https://github.com/markdown-it/markdown-it/blob/master/docs/examples/renderer_rules.md)接入库内链接，并关闭原始 HTML。

## DOCX 与文字版 PDF（P5）

本地 Python 3.10+ 安装可选依赖，未安装时 Markdown、浏览和搜索仍可使用：

```sh
python -m pip install -r requirements-formats.txt
```

默认调用 PATH 中的 `python`；有多个环境时，可在仓库外实例配置的 `imports.python` 指定解释器绝对路径。Python 以隔离模式运行，不加载当前目录或用户 site-packages；依赖须安装到该解释器环境。采用 python-docx 1.2.0（MIT）、pypdf 6.19.0（BSD-3-Clause）及 Pillow 12.2.0（MIT-CMU）。解析不调用模型或网络，不读取外部关系、执行宏或启动 Office。依据 [python-docx 文档](https://python-docx.readthedocs.io/en/latest/api/document.html)、[pypdf 文字说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)和[图片说明](https://pypdf.readthedocs.io/en/stable/user/extract-images.html)接入现有库能力。

每次最多 16 MiB，PDF 最多 200 页；子进程 45 秒超时。DOCX 展开最多 64 MiB / 3000 条目，正文最多 10000 块；提取文字最多 4 MiB，图片最多 300 张 / 32 MiB。超限或整体损坏时拒绝创建任务；依赖缺失显示安装说明，不影响其他入口。PDF 单页文字或图片失败保留已解析部分并明确标记，不宣称全文成功。

DOCX 保留正文顺序、已知标题样式、表格文本和嵌入图片原始字节；使用正文块序号标位置，页码不可用。文本框按所在正文块提取段落文字，以等宽块保留代码、日志换行与缩进，不还原浮动排版。合并/嵌套表格、修订、批注、页眉页脚、图表和嵌入对象不保证完整表达，须对照原件。未定位的包内图片也保留并标注位置不可用。

PDF 按页生成布局文字和图片引用。表格间距保留为等宽文字，不推断表格结构或标题层级；复杂多栏、旋转文字和特殊字体仍需原件对照。无有效文字页标记为可能的扫描页或空白页，需要 OCR / 人工核对；已有文字层也不证明图中文字已识别。图片使用解析库提取的字节，可能经过解码封装，不承诺与 PDF 内压缩流逐字节相同；完整 PDF 原件保持字节不变。加密 PDF 拒绝导入。矢量图、注释、表单和内嵌附件保留于原件，不宣称已提取。

产物为 `原文.docx` / `原文.pdf`、`原始资料卡.md`、`解析正文.md`、`images/NNNN.ext`。非预览图片格式以 `.bin` 保留提取字节，仅下载。生成的名称不采用文档自带路径；全部摘要、相对路径、解析器版本和范围提示纳入审核版本。预览通过只读文件映射复用正式 Markdown 渲染器，无额外预览副本；暂存附件只允许读取同任务清单，正式写入前检查正文引用。旧 P4 任务及审核版本兼容，不迁移已批准资料。
